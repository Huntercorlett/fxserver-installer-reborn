# Patch notes (0.4.1 logs + SQL fix)

- `src/lib/core/workspaces.svelte.ts`: `captureActiveWorkspace` is untracked and only writes/persists when a value actually changed (fixes the Server Logs freeze: $effect <-> "workspace-settings-changed" feedback loop).
- `src/lib/features/fxserver/FxserverLogsPage.svelte`: effect only tracks `dataPath`/`profile`, setters run untracked; regex-free line parsing; long lines capped (4000 chars); render capped (1500 entries).
- `src/lib/modules/sqlDiagnostics.ts` (new) + `SqlRunnerPage.svelte`: on ERROR 1005 / errno 150 / 1215, inspects the real server (missing table, missing index, type mismatch, collation mismatch) and offers "Apply fix to SQL".
- `scripts/test-manager-safety.mjs`: stub for the new `svelte` import.
- Round 2: `runSqlWithForeignKeyRepair` now wraps BOTH the SQL File runner and the Query Console. Collation-mismatch FK failures on schema-only SQL are repaired and retried automatically (up to 8 columns); SQL containing INSERT/UPDATE/DELETE/DROP only offers the "Apply fix" button. Added InnoDB-engine check; removed a false "length mismatch" diagnosis (varchar lengths may differ in FKs).
- Round 3: Queries & Files -> "Generate collation fix" scans the selected database and writes SQL converting every table to utf8mb4_unicode_ci (review, then Run SQL), so resource/oxmysql SQL stops failing. Server-console FK/errno 150 lines now raise an in-app alert pointing to it.
- Round 4: collation fix drops and recreates affected foreign keys around the CONVERT (fixes ERROR 1832).
- Round 5: target collation is now an editable field next to "Generate collation fix" (match whatever your XAMPP database uses).
- Round 6: one-click "Fix database for FiveM" (utf8mb4_unicode_ci: scan, drop/recreate FKs, convert, run).
- Round 7: `services/mariadb/users.rs` sets passwords with `IDENTIFIED VIA mysql_native_password` (falls back to server default) so txAdmin/oxmysql (mysql2) can log in. Rust change is UNCOMPILED here - run `npm run tauri build` and report any compiler error.
- Round 8: `package-metadata.ps1` pins the installer to MariaDB 10.11 LTS (falls back to newest stable). Untested here (no PowerShell). Existing 12.x installs must be backed up, uninstalled and reinstalled into a NEW data dir, then restored.
- Round 9: txData detection. If the chosen folder is a profile folder (has config.json) or the server folder that contains txData, the app now corrects TXHOST_DATA_PATH + profile automatically. Rust: `has_root_config` added to TxDataProfilesResult (uncompiled here).
- Round 10 (0.4.2): `list_txdata_profiles_blocking` was throwing "Failed to inspect ...txData: os error 3" on a brand new server, because txData doesn't exist until fxserver.exe/cfx-server.exe has actually been run once. It now just returns an empty profile list instead of erroring. Same reason the preflight "Configured txData directory missing" check was blocking Start on a fresh install with no server run yet — dropped from Error to Warning. Also: Database Browser tree wasn't collapsing when you clicked an already-open database, it just kept re-selecting itself — fixed.
- Round 11: Website Hosting can now run PHP or Node instead of only static files. New per-site "runtime" (static/php/node) + a backend command and backend port. When not static, the app spawns your command (e.g. `php -S 127.0.0.1:8901 -t .` or `node server.js`) in the site folder and every request on the site's own port is spliced straight through to it at the raw TCP level — no parsing, no headers touched, no caching added on our end, so whatever the app sends back is exactly what the visitor gets. Backend process is killed when the site stops. Rust: `services/website.rs` gained `Runtime`, `spawn_backend`, `proxy_connection`; `SiteConfig` gained `runtime`/`backendCommand`/`backendPort` (uncompiled here, run `npm run tauri build`).
- Round 12: PHP mode reworked to actually match XAMPP instead of needing a manually-started `php -S` process. Site config field `backendCommand` now holds the path to php-cgi.exe for PHP sites specifically. `.php` files anywhere in the site folder run through it automatically (fresh php-cgi process per request, CGI/1.1 env vars + headers + POST/PUT/PATCH/DELETE body forwarded on stdin), while every other file in that same folder still serves as a plain static file on the same port — no separate process, no separate port, drop files in and go. Directory requests try index.php before index.html/htm, same priority order as XAMPP's htdocs. Request parsing gained real header capture (`Request.headers`) and body reading (`read_body`, capped at 32MB, chunked bodies rejected with 501 since real browsers/PHP clients always send Content-Length) — static and Node sites are untouched by this, they never read a body. `Reply.headers` changed from `&'static str` to owned `String` so CGI response headers (Set-Cookie, custom headers, etc.) can pass through. New: `route_php`, `execute_php`, `parse_cgi_output`, `is_php_path`, `is_blocked_for_php`, `lookup_for_php`. Node mode is unchanged (still reverse-proxied to your own server, since a Node app is already its own HTTP server, not a script Apache runs per-file). Note: unlike Apache, there is still no directory-listing page when a folder has no index file — that's an existing deliberate safety choice in this server, not something this patch touched. Uncompiled here — build and test file uploads/cookies/sessions before relying on it, since this is the part of the diff most likely to need a follow-up fix.
